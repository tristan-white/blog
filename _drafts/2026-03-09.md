This guide explains how to set up neovim and the new vim.pack plugin manager.

It installs the basic features and nice-to-haves that are common in VSCode, such as:

- a python LSP, which provides:
  - go-to-definition (ie Ctrl+click in VSCode)
  - reference lookup (find all references to a variable in your project)
  - Autocompletion
- colorschemes
- file browser
- a fuzzy file finder and word searcher
- a markdown renderer

The purpose of every line in the neovim config is explained so you know how to change it according to your preferences.

If you're not sure whether neovim will fit your needs, or which neovim plugin manager and plugins you want, start with with [why](#why). Else, skip to [requirements](#requirements)

## Why

You probably don't need neovim.

Everytime I asked a neovim user if I should switch from VSCode, they said nah, probably not if I was happy with VSCode (I was).

That being said, if any of these reasons apply to you, you may want to switch:

- You are tired of setting up vscode everytime you switch to a new workstation, and you want consistent setup that's easy to install.
- You work in offline dev environments (IMO neovim dependencies are easier to get working than VSCode)
- You feel the mouse is slowing you down.

But the more I switch workstations and have to work in non-internet connected environements, the more time I've had to spend configuring VSCode plugins.

## Requirements

- neovim 12.0+ (that is when the [vim.pack](https://neovim.io/doc/user/pack/) plugin manager was added)

## Adding Dependencies

This is pretty simple, so lets do it first.

1. [Pick a colorscheme](https://vimcolorschemes.com/i/trending). 
2. Copy and paste the github link to that colorscheme into the [vim.pack.add](https://vimcolorschemes.com/i/trending) function.
3. Enable it.

```lua title="~/.config/nvim/init.lua"
vim.pack.add({
  "https://vimcolorschemes.com/i/trending"
})
vim.cmd.colorscheme("gruvbox")
```
